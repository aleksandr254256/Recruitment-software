# Recruitment-software
Recruitment Department: Candidate and Application Tracker A single-file HTML dashboard for the recruitment department. It replaces manual reporting in Excel or Google Sheets: an analyst simply loads two CSV exports directly into the browser to generate an interactive dashboard suitable for both day

Зачем это существует

Отдел подбора персонала ведёт учёт кандидатов и заявок на подбор в Google Sheets с ручными формулами. Это медленно, легко ломается и не масштабируется на ~26 000 строк истории кандидатов. Этот инструмент читает те же исходные данные (два CSV-экспорта) и строит из них живой, интерактивный, фильтруемый дашборд — без единой ручной формулы в самих данных.

Стек
Чистый HTML/CSS/JavaScript, без сборки и без зависимостей на этапе разработки
PapaParse — парсинг CSV в браузере
SheetJS (xlsx) — экспорт таблиц в .xlsx
Шрифты и цвета — по брендбуку компании (Verdana, Veles Blue Pantone 287C, Veles Orange Pantone 151C и т.д.)
Быстрый старт
Скачайте tracker-kandidatov.html (или как вы его назовёте) и откройте в браузере.
Загрузите файл «Сбор данных» — это обязательно, весь дашборд строится вокруг него.
Загрузите файл «Отчет» — нужен для вкладок с заявками и потребностью (без него доступна только часть функций).
Дальше — работайте с фильтрами и вкладками. Файлы нужно перезагружать вручную каждый раз, когда нужен свежий срез — автообновления нет и не планируется (это осознанное решение: инструмент детерминированный и не имеет скрытых сетевых зависимостей).
Требования к входным файлам

«Сбор данных» (CSV, заголовки в первой строке) — построчный лог кандидатов, ключевые столбцы: Рекрутер, Дата отклика, Источник, ФИО, Гражданство, Контакты, Заявка, ОП, Проект, Участок / Отдел / Группа, Должность, через ОП / ЦТС, Статус, Дата статуса, Дата готов. / БИЛЕТА, Комментарий, Предыдущий статус, Аналитика отказов.

«Отчет» (CSV, заголовки во второй строке файла — так экспортирует источник) — свод по заявкам заказчика: № Заявки, ОП, Проект, Участок / Отдел / Группа, вид, Должность, Категория, Статус, Кол - во вакансий, на ОП, Куплен билет, Осталось, В работе, Дедлайн, Дата поступления заявки.

Названия столбцов должны совпадать буквально (с учётом пробелов и регистра) — парсер их не подбирает по смыслу.

Что внутри — по вкладкам

Дашборд
Снэпшот на сегодня, не зависит от фильтра «Период». Сверху вниз:
Два кольцевых индикатора — «Открыто заявок из N» и «Осталось закрыть вакансий из N» — оба следуют за фильтром «Год» (конкретный год или сумма по всем годам).
Баннер «Динамика на этой неделе» — сколько вакансий открылось и закрылось за текущую календарную неделю (Пн–Вс), не зависит от фильтра «Период».
Столбчатая диаграмма «Потребность по ОП» — закрыли / осталось, по площадкам.
Таблица «Потребность по заявкам» — категория × ОП, сумма «Кол-во вакансий».
Таблица «Потребность по категориям» — ИТР / ИТР-Лин. / РОП / РОП-Сварщик.
«Этапы воронки» — 13 статусов плитками, с недельной динамикой «+N за нед.» под каждым числом, и счётчиком «В работе» в шапке блока.
Сводка за период

Управляется общим переключателем «Период» (День / Неделя / Месяц / Все) сверху. Карточки: новые отклики, активность по воронке, направлено. Ниже — сворачиваемые блоки: «Закрыли за неделю» (с разбивкой «куда» по проектам и «кого» по должностям), список новых откликов, активность в разрезе статусов.

Оперативный отчёт

Открытые заявки (с экспортом в Excel и итоговой строкой), список «В работе» (тоже с экспортом), диаграмма «В работе по ОП», и сводная таблица «Готовность к выезду» (Должность × Неделя, горизонт 1 месяц, с drill-down по клику на ячейку).

Отказы

Сколько откликнулось за период и сколько из них отказано в этот же период, с разбивкой по причинам и диаграммой.

Заявки на контроле

Заявки, открытые 60+ дней без движения («зависшие»), плюс отдельный диагностический блок — открытые заявки, у которых вообще нет ни одного привязанного кандидата в «Сбор данных» (обычно из-за несовпадения номера заявки в двух файлах).

Рекрутеры

Нагрузка и показатели по каждому рекрутёру (доходимость, % доходимости, среднее число дней без смены статуса), плюс эффективность передачи кандидатов между рекрутёрами (см. методологию ниже).

Как пользоваться

Встроенная документация внутри самого инструмента — объясняет каждый фильтр и каждую вкладку человеческим языком.

Ключевая бизнес-логика

Ничего из этого не «интуитивно понятно» — каждое правило было явно согласовано в процессе работы над инструментом. Если меняете код — сверяйтесь с этим списком.

Неделя (КН) считается инструментом самостоятельно по дате события — ISO 8601, Пн–Вс. Номер недели, который, возможно, есть в исходном файле, не используется.
«В работе» (STATUS_GROUP_1): Согласование, Сбор документов, Служба безопасности, Медосмотр, Оффер, Мобилизация, на ЦТС.
«Финал» / «Отправлено» (STATUS_GROUP_2): Куплен билет, Трудоустроен, на ОП.
«На ОП» на вкладке «Заявки» (NA_OP_3, отдельная от STATUS_GROUP_2 группа): Трудоустроен, Перевод, на ОП.
«Осталось» по заявке = Кол-во вакансий − Куплен билет − (Трудоустроен + Перевод + на ОП) — считается по кандидатам, привязанным к конкретной заявке (поле «Заявка» = «№ Заявки»), а не берётся из готового столбца файла «Отчет» (готовый столбец бывает неточным).
Кольца на Дашборде за выбранный год: знаменатель — все заявки/вакансии, поступившие в этом году (любой статус); числитель («осталось закрыть») — только по заявкам, которые сейчас в статусе «Открыта» (закрытая заявка выбывает из остатка целиком, её кандидатов по устаревшим статусам не пересчитываем).
«Через ЦТС» — это канал маршрутизации (столбец «через ОП / ЦТС», значения «Кингисепп ЦТС» и «АЦ Москва»), а не статус. Не путать со статусом «на ЦТС» — это разные вещи и считаются раздельно.
«+N за нед.» на плитках воронки — это НЕ поток/переходы между этапами. Это снэпшот: сколько кандидатов сейчас стоят в этом статусе, и дата последней смены статуса у них — на этой неделе. Числа на соседних этапах не обязаны биться друг с другом — это разные, часто пересекающиеся, но не идентичные группы людей.
Уволенные рекрутёры (список зашит в EXCLUDED_RECRUITERS) исключаются из данных целиком при загрузке, на уровне всего инструмента, а не только из вкладки «Рекрутёры».
Восстановление ОП/Проекта/Участка: если у кандидата эти поля пустые, но «Заявка» совпадает с известным «№ Заявки» в «Отчете» — недостающие поля подтягиваются автоматически оттуда при загрузке (работает независимо от порядка загрузки файлов).
Эффективность передачи между рекрутёрами: связка «от кого — кому» не хранится в данных напрямую и восстанавливается по приоритету методов: (1) упоминание рекрутёра в комментарии, (2) совпадение ФИО + ОП + Проект + более поздняя дата, (3) совпадение телефона. Передачи, которые не удалось разрешить ни одним методом, честно исключаются из статистики, а не приписываются наугад.
«Зависшая» заявка — открыта 60+ дней с даты поступления. Порог задан константой, при необходимости меняется в одном месте.
Категории (ИТР / ИТР-Лин. / РОП / РОП-Сварщик) определяются по должности через явный справочник, а не по ключевым словам. Должность, которой нет в справочнике, помечается «Требует дополнительного уточнения» — инструмент не угадывает.
Все текстовые справочники (нормализация ОП, проектов, участков, должностей, гражданства, источников, причин отказа) вынесены в объекты в начале <script> — правки конкретных опечаток в исходных данных вносятся туда, а не в логику расчётов.
Известные ограничения
Столбчатая диаграмма «Потребность по ОП» использует сжатую (не линейную) шкалу высоты столбцов, чтобы маленькие площадки было видно рядом с крупными — абсолютные значения точны (подписаны на столбцах), но сравнивать площадки «на глаз» по высоте нельзя.
Цифры «осталось закрыть» на Дашборде и в Google Sheets могут не совпадать, если в таблице есть ручные корректировки поверх этих же двух файлов — инструмент считает строго по формуле из CSV, без ручных поправок.
Расчёты, завязанные на «текущую дату» (недельная динамика, «+N за нед.», «зависшие заявки»), используют системную дату браузера на момент открытия страницы.
Приватность

Все вычисления происходят в браузере. Файлы не загружаются ни на один сервер — сеть не используется вообще, кроме однократной загрузки шрифта и двух библиотек (PapaParse, SheetJS) с публичных CDN при первом открытии страницы.
